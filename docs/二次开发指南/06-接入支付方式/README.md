# 接入支付方式

## 1. 现有支付抽象

代码中已有 Epay、Stripe、Creem、Waffo 等支付路径，路由集中在 `router/api-router.go`，处理器位于 `controller/`，订单和额度结算位于 `model/topup.go`、`model/subscription.go` 及相关 service。新增支付应复用订单状态和结算方法，而不是直接修改用户余额。

## 2. 标准流程

```text
创建待支付订单 → 返回支付参数/跳转地址
      ↓
第三方异步 webhook/同步 return
      ↓
验签、校验商户/金额/订单号/支付状态
      ↓
事务内幂等完成订单 → 增加额度/订阅 → 记录审计日志
```

## 3. 实现步骤

新增 provider 常量、配置项和管理后台设置；增加创建支付、异步通知、同步返回路由；实现原始请求验签；调用现有订单完成逻辑；锁定订单并检查订单所属 provider，防止跨支付方式误完成；对重复通知返回成功但不得重复加款。

## 4. 安全与验证

金额必须以服务端订单为准，不能信任回调金额；验证签名、商户号、币种、订单状态和回调来源；回调处理不记录密钥或完整支付凭证。测试成功、失败、伪造签名、金额不符、重复回调、并发回调、超时和退款。支付属于认证/资金敏感流程，按 OWASP ASVS、Authentication/Session guidance 审查会话和管理权限。
