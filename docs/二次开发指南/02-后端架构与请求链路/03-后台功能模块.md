# 后端功能模块详解

## 用户、认证和权限

`middleware/` 在 API 入口执行 TokenAuth、UserAuth、限流、CORS、代理信任和审计；`model/user.go`、token/session 相关模型保存身份；`service/authz/` 通过 Casbin 判断角色和资源权限。认证失败应统一错误，不暴露用户是否存在；认证审计不能记录密码、验证码、私钥或可用 token。

## 渠道、分组和模型映射

Channel 保存 provider 类型、BaseURL、密钥、启用状态和设置；Ability 将 group、model、channel、priority、weight 关联起来。请求先以客户端模型查 Ability，模型映射只影响上游模型和价格身份，不应改变用户看到的原始请求名。多 key 渠道还要记录实际 key index，便于失败隔离。

## 额度、定价和消费日志

`relay/helper/price.go` 读取模型价格和组倍率；`service/token_counter.go` 负责 token 估算；`service/billing.go`/`service/quota.go` 负责预扣、结算和退款；`model/log.go` 保存消费和审计信息。计费字段有金额、倍率、输入/输出 token、图片数量、工具数量和 quota，修改时先阅读 billing 规则并保护整数边界、幂等和并发扣费。

## 支付和订阅

支付创建在 controller，订单模型在 `model/topup.go`/`model/subscription.go`，完成订单必须经过验签、金额核对、provider 核对和事务幂等。余额增加不能由前端直接触发；回调重复到达必须安全返回。

## 任务插件和异步任务

`plugins/tasks/` 描述任务协议；`pkg/jsplugin/` 执行插件；`relay/relay_task.go` 提交、轮询、获取结果并与 billing 关联。任务类请求在提交前锁定可承担的额度，轮询超时、连续失败和最终失败必须退款或按规则结算。

## 日志、策略和运维

RequestPolicy 记录每次 attempt 的开始、失败、成功和拒绝；策略决定是否重试、是否封禁渠道和是否收取违规费用。后台同步任务刷新渠道、缓存和模型能力。运维需监控 DB、Redis、上游错误率、请求延迟、流式首包和任务积压。
