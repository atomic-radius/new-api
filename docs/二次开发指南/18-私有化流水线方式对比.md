# 私有化流水线方式对比

## 1. 流水线的共同阶段

```text
提交代码 → 静态检查 → 单元测试 → 构建前端/后端 → 构建镜像
→ 漏洞扫描/签名 → 推送私有 Registry → 开发部署
→ 集成测试 → 测试部署 → 人工审批 → 备份 → 生产部署
→ 冒烟检查 → 监控 → 必要时按 digest 回滚
```

每次发布使用不可变 Git SHA 和镜像 digest，禁止使用 `latest`。生产流水线不能重新编译“同一个版本”，而应提升测试阶段已经验证过的同一份镜像。

## 2. 方式一：GitLab Self-Managed 一体化流水线

```text
GitLab + GitLab Runner + GitLab Registry + Kubernetes + Helm/Kustomize
```

GitLab 管理代码、合并请求、权限、流水线、Registry、审批和审计；Runner 在内网执行 Go、Bun、镜像构建和 Helm 部署。优点是组件少、权限集中、上线快。缺点是生产集群状态由 CI 主动修改，需要额外做 drift 检查。

适合：大多数私有化团队、首次建设平台、小到中等规模团队。

## 3. 方式二：Jenkins + Harbor + Kubernetes

```text
GitLab/Gitea + Jenkins + Harbor + Kubernetes + Helm
```

Jenkins 插件生态和流水线自由度最大，Harbor 提供扫描、签名、复制和项目权限。缺点是 Jenkins、插件、凭据、Agent 和 Harbor 都要独立维护，升级面大，安全基线复杂。适合已有 Jenkins 运维能力的组织，不建议新团队仅因“灵活”而选它。

## 4. 方式三：CI + Argo CD GitOps

```text
GitLab CI（测试/构建） → Registry
GitLab 配置仓库 → Argo CD → Kubernetes
```

CI 不直接拥有生产集群写权限，只更新经过审批的部署配置；Argo CD 负责持续对账、状态可视化和回滚。安全性、审计性和状态一致性最好，但需要额外维护 Argo CD、配置仓库、同步策略和权限模型。

## 5. 方式四：Tekton/Argo Workflows 云原生流水线

流水线任务本身运行在 Kubernetes 内，适合多租户、动态任务和平台工程团队。它的扩展性最好，但 CRD、权限、缓存、调试和升级成本也最高。除非团队已经熟悉 Kubernetes 原生流水线，否则不作为第一套私有化方案。

## 6. 方式五：手工 kubectl/Helm

最初部署最快，但不可审计、容易漏步骤、容易产生集群漂移，无法稳定复现。只能作为应急手段，不能作为长期生产发布方式。

## 7. 综合比较

| 方式 | 安全性 | 简洁性 | 效率 | 审计/回滚 | 运维复杂度 |
| --- | --- | --- | --- | --- | --- |
| GitLab 一体化 | 高 | 最高 | 高 | 高 | 低 |
| Jenkins+Harbor | 高 | 中 | 高 | 高 | 高 |
| CI+Argo CD | 最高 | 中 | 高 | 最高 | 中高 |
| Tekton/Argo Workflows | 最高 | 低 | 高（规模化后） | 高 | 最高 |
| 手工 Helm | 低 | 表面简单 | 低 | 低 | 低但风险高 |

## 8. 三个“最优”答案

### 最安全

GitLab Self-Managed + 私有 Runner + Harbor + Cosign + Vault/External Secrets + Kubernetes + Argo CD + NetworkPolicy + 审计监控。生产集群只接受签名镜像和配置仓库中的审批提交，CI 不直接持有生产写权限。

### 最简洁

GitLab Self-Managed + GitLab Runner + GitLab Registry + Kubernetes + Helm。阶段为 `verify → build → push → deploy-dev → test → manual deploy-prod`，组件少、学习成本低。

### 最佳平衡（推荐）

GitLab Self-Managed + Runner + Harbor 或 GitLab Registry + Kubernetes + Helm/Kustomize + Vault/External Secrets + Prometheus/Grafana。第一阶段不引入 Argo CD；当集群超过多个环境、需要强审计或频繁回滚时再增加 Argo CD。

## 9. 选择决策

- 没有现成平台：选 GitLab 一体化。
- 已经有 Jenkins/Harbor：保留既有平台，不要为了追求“新”而重建。
- 有严格生产隔离和审计要求：增加 Argo CD、Vault、镜像签名。
- 有大量团队和多租户流水线：评估 Tekton/Argo Workflows。
- 任何情况下：不要把手工发布作为唯一生产方案。
