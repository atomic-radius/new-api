# 测试环境流水线部署

测试环境验证可发布镜像和真实基础设施交互。前端编译进 Go 镜像，应用部署在独立 Kubernetes Namespace，数据库和 Redis 使用测试专用实例。

## 流水线

```text
Checkout 固定提交
  ↓ 前端 typecheck、测试
  ↓ Go vet、build、test
  ↓ Docker build
  ↓ 推送 registry/new-api:<git-sha>
  ↓ 部署测试 Namespace
  ↓ rollout status
  ↓ API、迁移、模型和计费验证
```

仓库已有 Dockerfile 多阶段构建。测试镜像必须使用提交 SHA，不能使用 latest：

```bash
docker build --pull -t registry.example.com/new-api:${GIT_SHA} .
docker push registry.example.com/new-api:${GIT_SHA}
```

## Namespace 和 Secret

```bash
kubectl create namespace new-api-test
kubectl -n new-api-test create secret generic new-api-secrets \
  --from-literal=SESSION_SECRET=<test-random-secret> \
  --from-literal=CRYPTO_SECRET=<test-random-secret> \
  --from-literal=SQL_DSN='postgresql://new_api_test:<password>@postgres:5432/new_api_test' \
  --from-literal=REDIS_CONN_STRING='redis://:<password>@redis:6379/1'
```

实际项目应使用 External Secrets 或云密钥管理器，生产 Secret、数据库和 Redis 不得进入测试环境。

## 测试 Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: new-api
spec:
  replicas: 1
  selector:
    matchLabels: { app: new-api }
  template:
    metadata:
      labels: { app: new-api }
    spec:
      containers:
        - name: new-api
          image: registry.example.com/new-api:COMMIT_SHA
          ports:
            - name: http
              containerPort: 3000
          envFrom:
            - secretRef: { name: new-api-secrets }
          readinessProbe:
            httpGet: { path: /api/status, port: http }
            periodSeconds: 5
          livenessProbe:
            httpGet: { path: /api/status, port: http }
            initialDelaySeconds: 20
          resources:
            requests: { cpu: 250m, memory: 512Mi }
            limits: { cpu: '2', memory: 2Gi }
---
apiVersion: v1
kind: Service
metadata:
  name: new-api
spec:
  selector: { app: new-api }
  ports:
    - name: http
      port: 80
      targetPort: http
```

## 部署和验证

```bash
kubectl -n new-api-test set image deployment/new-api new-api=registry.example.com/new-api:${GIT_SHA}
kubectl -n new-api-test rollout status deployment/new-api --timeout=5m
kubectl -n new-api-test get pods,svc
kubectl -n new-api-test port-forward svc/new-api 3000:80
curl --fail-with-body http://127.0.0.1:3000/api/status
```

验证顺序：Pod Ready、status、登录、模型列表、非流式请求、SSE、Redis 限流、额度结算、重启恢复。测试请求应使用测试模型或可控上游。

应用启动会执行 AutoMigrate，必须验证新库启动、已有库升级和第二次启动幂等。

## 失败和回滚

```bash
kubectl -n new-api-test logs deployment/new-api --tail=200
kubectl -n new-api-test describe pod -l app=new-api
kubectl -n new-api-test rollout history deployment/new-api
kubectl -n new-api-test rollout undo deployment/new-api
```

## 通过标准

镜像来自固定 SHA；探针通过；数据库迁移新建、升级和幂等通过；登录、权限、Token、模型、非流式和 SSE 通过；Redis 可连接；失败请求不错误扣费；重启 Pod 后数据仍在；CI 保存测试报告和镜像 SHA。
