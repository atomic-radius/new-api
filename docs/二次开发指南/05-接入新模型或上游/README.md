# 接入新模型或上游

## 1. 优先使用配置接入

如果上游兼容已有协议，通常不需要写 Go 适配器：在管理后台创建 Channel，填写类型、Base URL、密钥、模型列表、分组、优先级和模型映射，测试渠道后配置价格。先验证 `/v1/models`、最小 chat、流式和错误响应。

## 2. 需要代码适配的情况

当认证签名、请求字段、响应结构、流格式、图片/音频协议或异步任务语义不同，才修改 `relay/` 对应 adaptor、`types/`、协议转换和渠道常量。检查 `StreamOptions` 支持列表；可选标量字段使用指针和 `omitempty`，保留显式 0、0.0、false。

## 3. 接入清单

1. 明确请求/响应/流协议和错误码。
2. 增加渠道类型或复用现有类型。
3. 编写转换、认证、超时和重试逻辑。
4. 补充模型价格、token 估算或上游 usage 映射。
5. 测试文本、工具调用、多模态、流式、取消、超时、429/5xx。
6. 在管理后台增加必要配置和 i18n 文案。
7. 运行根模块与独立 `relaykit`/`tokenkit` 构建。

## 4. 不要做的事

不要在 controller 中拼接上游协议；不要把 provider key 写进日志或测试样例；不要用非指针 `omitempty` 静默丢弃客户端显式零值；不要只以一次成功请求宣称兼容。
