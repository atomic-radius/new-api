# 开发环境流水线部署

开发环境采用本地代码、Docker Compose 基础设施和 Bun 前端热更新：Go 服务运行在 3000，PostgreSQL 和 Redis 运行在 Compose 网络中，React 开发服务器运行在 5173。

## 架构

```text
浏览器 :5173
  ↓ Rsbuild 代理
new-api-dev :3000
  ├─ PostgreSQL :5432
  └─ Redis :6379
```

仓库现有 `docker-compose.dev.yml` 和 `Dockerfile.dev` 已覆盖这套结构。开发数据库使用独立 Docker volume，不得连接生产数据库。

## 初始化和启动

```powershell
cd Y:\project\new-api\new-api
docker compose -f docker-compose.dev.yml up -d --build
docker compose -f docker-compose.dev.yml ps
docker compose -f docker-compose.dev.yml logs -f new-api
```

验证后端：

```powershell
Invoke-WebRequest http://127.0.0.1:3000/api/status
```

启动前端：

```powershell
cd web
bun install --frozen-lockfile
bun run dev
```

浏览器访问 `http://localhost:5173`。Rsbuild 会把 `/api`、`/v1`、`/pg` 请求代理到 3000。

## 开发变量

开发环境至少设置：

```text
SQL_DSN=postgresql://root:<local-password>@postgres:5432/new-api
REDIS_CONN_STRING=redis://redis:6379
SESSION_SECRET=<local-random-secret>
SESSION_COOKIE_SECURE=false
TZ=Asia/Shanghai
```

本地 HTTP 必须保持 `SESSION_COOKIE_SECURE=false`；使用 HTTPS 测试时再设置 `SESSION_COOKIE_TRUSTED_URL`。

## 每次改动的流水线

```text
创建分支
  ↓ 修改 Go、React 或配置
  ↓ 前端 typecheck 和测试
  ↓ Go fmt、vet、test
  ↓ Compose 启动 PostgreSQL、Redis、Go
  ↓ 验证登录、API、模型请求和数据库写入
  ↓ 提交 Pull Request
```

推荐命令：

```powershell
cd web
bun run typecheck
bun run test
cd ..
gofmt -w <modified-go-files>
go vet ./...
go test ./...
docker compose -f docker-compose.dev.yml up -d --build new-api
```

修改 Go 后只需重建后端容器；修改 React 时由 Bun 热更新。

如果修改 `relaykit/` 或 `tokenkit/`，必须在对应模块独立验证：

```powershell
cd relaykit
$env:GOWORK='off'
go build ./...
cd ..\tokenkit
$env:GOWORK='off'
go build ./...
```

## 数据库验证

开发阶段用 PostgreSQL 模拟生产。涉及模型、索引或迁移时，至少验证：新库启动成功、第二次启动幂等、已有数据可升级、接口读写正常。项目要求的数据库兼容改动还必须另外验证 SQLite、MySQL 和 PostgreSQL 三种数据库。

## 重置开发环境

```powershell
docker compose -f docker-compose.dev.yml restart
docker compose -f docker-compose.dev.yml down
docker compose -f docker-compose.dev.yml down -v
```

最后一条会删除开发数据，只能在本地使用。

## 进入测试环境的标准

- `bun run typecheck` 和受影响前端测试通过；
- 根 Go 模块 `go vet ./...`、构建和受影响测试通过；
- 独立模块验证通过；
- PostgreSQL、Redis 和 Go 容器健康；
- 登录、流式模型请求、额度和数据库写入完成验证；
- 日志中没有密码、API Key、Token 或聊天敏感内容。
