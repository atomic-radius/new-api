# 私有化高效发布实施手册

本文给出一套可落地的 GitLab Self-Managed + 私有 Runner + Registry + Kubernetes + Helm 流程。示例中的域名、镜像地址和 Helm 目录是占位符，需替换为实际内网地址；仓库当前不保证已经存在 `deploy/helm`。

## 1. 建议目录

```text
deploy/
  helm/new-api/             # Deployment、Service、Ingress、HPA、PDB
  values-dev.yaml
  values-test.yaml
  values-prod.yaml
ops/
  migrations/               # 迁移说明和验证脚本
  backup/                   # 数据库备份与恢复脚本
  policies/                 # NetworkPolicy、RBAC、Pod Security
```

## 2. GitLab CI 示例

```yaml
stages: [verify, build, scan, deploy-dev, test, deploy-prod]

variables:
  IMAGE: registry.intra.example/new-api/new-api
  IMAGE_TAG: $CI_COMMIT_SHA

frontend:
  stage: verify
  image: registry.intra.example/base/bun:1.4.0
  script:
    - cd web
    - bun install --frozen-lockfile
    - bun run typecheck
    - bun run test

backend:
  stage: verify
  image: registry.intra.example/base/golang:1.26
  script:
    - mkdir -p web/dist
    - touch web/dist/index.html
    - go vet ./...
    - go test ./...
    - GOWORK=off go build ./...
    - cd relaykit; GOWORK=off go build ./...
    - cd ../tokenkit; GOWORK=off go build ./...

build-image:
  stage: build
  script:
    - buildctl build --frontend dockerfile.v0 --local context=. --local dockerfile=. --output type=image,name=$IMAGE:$IMAGE_TAG,push=true

scan-image:
  stage: scan
  script:
    - trivy image --exit-code 1 --severity HIGH,CRITICAL $IMAGE:$IMAGE_TAG
    - cosign sign --key env://COSIGN_PRIVATE_KEY $IMAGE:$IMAGE_TAG

deploy-dev:
  stage: deploy-dev
  script:
    - helm upgrade --install new-api ./deploy/helm/new-api --namespace new-api-dev --create-namespace --set image.repository=$IMAGE --set image.tag=$IMAGE_TAG

test:
  stage: test
  script:
    - kubectl -n new-api-dev rollout status deployment/new-api --timeout=5m
    - ./ops/smoke-test.sh https://new-api-dev.intra.example

deploy-prod:
  stage: deploy-prod
  when: manual
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
  script:
    - helm upgrade --install new-api ./deploy/helm/new-api --namespace new-api-prod --set image.repository=$IMAGE --set image.digest=$IMAGE_DIGEST --atomic --timeout=10m
    - kubectl -n new-api-prod rollout status deployment/new-api --timeout=10m
```

生产 Job 使用 Protected Environment、受限 ServiceAccount 和最小 RBAC。构建 Job 不需要生产集群权限；部署 Job 不应读取数据库密码。真实环境中建议用 External Secrets 将 Vault 中的 Secret 映射到 Namespace。

## 3. 每个阶段做什么

1. **Verify**：前端 typecheck/test；根 Go 模块 vet/test/build；`relaykit`、`tokenkit` 使用 `GOWORK=off go build ./...` 独立验证。
2. **Build**：复用内部 Go、Bun 和基础镜像缓存，生成带 Git SHA 的镜像。
3. **Scan**：Harbor/Trivy 扫描，Cosign 签名，记录 SBOM；高危漏洞阻断生产。
4. **Deploy Dev**：自动部署开发 Namespace，使用开发数据库和 Redis。
5. **Test**：等待 Ready，执行健康检查、登录、模型转发、流式响应、会话、管理员权限和数据库迁移测试。
6. **Approve**：主分支合并、负责人审批、变更窗口和发布单齐备后才允许生产 Job。
7. **Backup**：迁移前备份数据库并验证备份文件可读；Redis 按业务需要启用持久化或仅作为可重建缓存。
8. **Deploy Prod**：使用已测试的同一镜像 digest，滚动发布，`maxUnavailable=0`，等待 Readiness 通过。
9. **Smoke/Monitor**：验证 `/api/status`、核心 API、模型调用、错误率、延迟、Pod 重启和数据库连接池。

## 4. Secret 与权限

- GitLab CI Variables 只保存非长期或加密引用；长期 Secret 放 Vault。
- `SQL_DSN`、`REDIS_CONN_STRING`、`SESSION_SECRET`、`CRYPTO_SECRET`、OAuth 和支付密钥禁止写入 YAML 明文。
- 生产 Runner 使用专用 ServiceAccount，只允许目标 Namespace 的 Deployment/Job 更新。
- 应用 ServiceAccount 不允许读取其他 Namespace Secret。
- 使用 NetworkPolicy 限制 Pod 只能访问数据库、Redis、内部模型和 DNS。
- 开启 Kubernetes Audit Log、GitLab 审计和 Registry 操作日志。

## 5. 回滚

优先回滚到上一个已验证 digest：

```powershell
helm history new-api -n new-api-prod
helm rollback new-api <REVISION> -n new-api-prod --wait --timeout 10m
kubectl rollout status deployment/new-api -n new-api-prod --timeout=10m
```

如果失败原因是数据库迁移，先停止继续发布，判断迁移是否向后兼容，再按备份恢复方案处理。不要只回滚应用镜像而忽略已经执行的不可逆迁移。生产发布应采用“先扩展字段、再发布代码、最后清理旧字段”的兼容迁移策略。

## 6. 高效实践

- 依赖和基础镜像使用内部缓存，减少重复下载。
- 测试阶段并行执行前端、后端和静态扫描；部署阶段串行执行迁移与应用发布。
- 构建产物只生成一次，开发、测试、生产提升同一 digest。
- 使用 HPA 扩展无状态 Go Pod；数据库和 Redis 的扩展必须单独设计，不能把 HPA 当作数据库高可用。
- 配置分层：公共 Helm 模板 + dev/test/prod values，避免复制三套 YAML。
- 每次发布记录 Git SHA、镜像 digest、数据库迁移版本、审批人、开始/结束时间和回滚点。

## 7. 验收标准

- 代码、镜像、日志、数据库、Redis 和备份均未经过公网，或所有外联均经过白名单代理并留痕。
- 新 Pod Ready 后旧 Pod 才退出，流式请求没有大面积中断。
- 任意发布可定位到 Git SHA 和镜像 digest。
- 开发、测试、生产使用不同 Namespace、数据库和 Secret。
- 能在演练环境完成数据库恢复、镜像回滚和 Secret 轮换。
- 数据库改动完成 SQLite、MySQL、PostgreSQL 的真实实例验证；无法验证时必须在发布记录中标明阻塞项，不能宣称已兼容。
