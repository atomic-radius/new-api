# 前端应用启动与状态层

## 1. `web/src/main.tsx` 逐行说明

1. 19-20 行导入 `QueryClientProvider`、TanStack Router。
2. 24-29 行导入构建信息、favicon、前端缓存、QueryClient 和状态查询。
3. 34-39 行初始化 i18n、生成路由树和全局 CSS。
4. 43-44 行初始化前端缓存与 build metadata。
5. 46-48 行创建 QueryClient；内部 500 错误导航到 `/500`。
6. 51-56 行创建 Router，注入 `queryClient` context，开启 intent preload。
7. 66-69 行寻找 `#root`，缺失即抛出启动错误。
8. 71-102 行先从缓存设置系统名称和 favicon，再通过 `ensureQueryData(statusQueryOptions)` 后台刷新，避免每个消费者各发一次 `/api/status`。
9. 103-117 行在 root 为空时挂载 StrictMode、QueryClient、主题、字体、方向和 Router Provider。

## 2. HTTP 层：`web/src/lib/http-client.ts`

- 49-56 行创建 Axios，`withCredentials: true`，默认禁止用户数据缓存。
- 58-75 行对 GET 按 session SID、URL、params 去重；请求完成后从 in-flight map 删除。
- 86-145 行响应拦截器处理 auth rotation、401 refresh、过期跳转和安全错误文案。
- 147-165 行请求拦截器注入 Bearer；带 `singleUseAuthorization` 或 security proof 的请求先获取新鲜授权，禁止用原请求重放敏感操作。

## 3. Query 层：`web/src/lib/query-client.ts`

默认 query stale 10 秒、窗口聚焦不自动刷新；开发环境不重试，生产最多三次且不重试 401/403。QueryCache 和 MutationCache 统一 toast，但 `meta.errorToast=false` 或自定义 `onError` 可以接管展示。

## 4. 认证布局

`web/src/routes/_authenticated/route.tsx:25-42` 在每个受保护页面加载前调用 `resolveAuthentication`，再检查 `auth.user` 和 `auth.accessToken`；缺失时带上原始 URL 重定向 `/sign-in`。`AuthenticatedLayout` 再渲染侧边栏、顶部导航和 `<Outlet>`，子页面只负责业务内容。
