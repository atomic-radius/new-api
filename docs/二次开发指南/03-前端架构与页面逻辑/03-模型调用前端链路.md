# 模型调用的前端链路

## 1. Playground 页面进入

`web/src/routes/_authenticated/playground/index.tsx:25-39` 先判断 `isSidebarModuleEnabled('chat','playground')`；禁用则重定向 dashboard；启用后把 `features/playground/Playground` 放入 `Main`。因此页面壳不发请求，模型和消息逻辑在 feature 内。

## 2. 模型列表和选择

Playground 的模型选择组件通过 feature API 调用 `/api/user/models` 或相关模型接口；`web/src/lib/api.ts:51-67` 的 `getUserModels/getUserGroups` 只是 Axios 包装并返回 `res.data`。Query 将模型列表缓存，选择模型后把 `model` 写入本地页面状态，不应把完整远程对象复制到全局 store。

## 3. 发送按钮到 HTTP

典型调用顺序是：

1. 输入框 state 收集 messages、model、stream、temperature、tools 等。
2. Zod/表单层检查 model 和消息非空，按钮在发送中禁用。
3. feature API 使用 `api` 或专用 SSE helper 请求 `/v1/chat/completions`；浏览器请求携带 `Authorization: Bearer`，管理台请求另带 Cookie。
4. `http-client.ts:161-165` 从 auth store 注入 token；需要 security proof 的管理操作走 147-160 行的新鲜授权分支。
5. stream 请求不能使用普通 JSON `response.data` 等待完整结果，而要逐 chunk 解析 SSE，按 `id/choices[].delta` 合并 assistant 文本、tool call 和 usage。
6. 每个 chunk 更新消息状态；结束帧将 loading 改为 completed；网络错误保留已生成文本并显示重试操作。

## 4. 与后端逐项对应

| 前端动作 | 后端对应 |
| --- | --- |
| 选择模型 | `/api/user/models` → 权限/分组/Ability 过滤 |
| 点击发送 | `/v1/chat/completions` → `router/relay-router.go:105` |
| Bearer 注入 | `TokenAuth` → token/user/group context |
| 请求体 JSON | `GetAndValidateTextRequest` → DTO/限制 |
| 等待响应 | `GenRelayInfo` → Channel 选择 → adaptor |
| 增量文本 | 上游 stream converter → OpenAI SSE |
| usage/额度 | response handler → billing settlement/log |
| 429/5xx | retry decision → 最终 JSON/SSE error，前端 toast/消息错误 |

## 5. 页面状态机

```text
idle
 └─ submit → validating
              ├─ invalid → form error → idle
              └─ valid → connecting
                           ├─ first chunk → streaming
                           ├─ done → completed → idle
                           ├─ abort → cancelled → idle
                           └─ error → failed → retry/idle
```

不要只用一个 `isLoading` 表示全部状态：连接中、已有部分输出、用户主动取消、服务端拒绝和网络失败的 UI 行为不同。重试时要明确是重新发送整条消息还是复用已保存的 assistant 内容，避免重复扣费或重复显示。

## 6. 逐行调试方法

在浏览器依次打断点：Playground route 的 `beforeLoad` → feature 的发送 handler → API/SSE helper → `http-client` request interceptor → Network 请求 → `controller.Relay` → 后端 adaptor。记录 request body 中的 model/stream、响应第一帧时间、最后 usage、HTTP 状态和前端最终消息状态；这样可以区分“按钮没触发、请求没发出、后端拒绝、上游失败、流解析失败、UI 未合并”六类问题。
